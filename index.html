nimble-som-test — Laya → REAPER music pipeline

Prompt with an English music idea — "gritty 90s boom bap for a late-night basement cipher" — and get a routed, rendered, multi-track REAPER project: Laya decides tempo, key, time signature, groove and the instrument palette; the engine renders per-instrument WAV + MIDI stems; bridge.lua builds the REAPER project and drives transport.

Run

./start.sh --daemon          # REAPER + bridge, detached; do this first
.venv/bin/python tui.py      # interactive: type genre ideas, repeat

One-shot:

.venv/bin/python setup.py "spooky ghost music for a spooky party" --play

Routing + rendering without REAPER: append --render-only (needs no JACK). Every instrument scoring >= 0.6 confidence is routed by default; cap with --max-instruments N and cut down by hand in REAPER.

Layout

  • engine.py — stdlib synth: decisions → per-instrument WAV + MIDI
  • pipeline.py — Laya routing, render memoization, REAPER bridge client
  • setup.py — one-shot CLI: idea → decisions → render → REAPER
  • tui.py — interactive prompt loop (idea, bars, max tracks, autoplay)
  • bridge.lua — REAPER ReaScript: file IPC (state.json heartbeat, run/cmd commands)
  • stems.py — standalone 4-bar demo stem generator (stdlib only, no deps)
  • smoke_laya.py — router smoke test (no REAPER needed)

Setup

python -m venv .venv
.venv/bin/pip install -r requirements.txt

The first routing run downloads the Laya checkpoint from Hugging Face (convaiinnovations/laya) into ~/.cache/huggingface.
